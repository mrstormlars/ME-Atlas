# Static site generator

Reference for the founder and for agents. Code: `src/me_atlas/site.py` (build), `src/me_atlas/glossary.py` (glossary model), templates in `src/me_atlas/templates/`, `src/me_atlas/static/site.css` and `site.js`. Plan: `docs/plan-site-generator.md`. Page content follows `docs/ME-Atlas-functional-spec.md` sections 3 to 6; where this page and the spec differ, the spec wins.

## Build and preview

```bash
uv run python -m me_atlas.site build                  # approved cards only, into build/
uv run python -m me_atlas.site build --drafts         # also drafts/, as a draft preview
uv run python -m me_atlas.site build --out some/dir   # another output directory
```

Open `build/index.html` in a browser. Every page works from `file://` (all links are relative); there is nothing to serve.

The site is built in every language that has a file in `content/i18n/`: English at the top of the output directory and Norwegian in `build/nb/`, same pages, one shared `static/`. All fixed text comes from the string files; see `docs/translation.md` for the string files, the Norwegian glossary, card translations, the language selector and what a page shows when a translation is missing or out of date. Where this page says "the page says X", that is the English text; the Norwegian string is in `content/i18n/nb.yaml`.

- The build validates every input card (the same rules as `uv run python -m me_atlas.cards validate`), the change log and the glossary first. If anything fails it prints every problem, exits with code 1 and writes nothing (an earlier build stays as it was).
- The output directory is emptied before each build. A directory that is not empty and not a previous build (no `.me-atlas-build` marker file) is never deleted; the build stops instead.
- The citation check (`me_atlas.citations`) is not part of the build; it needs the local cache.
- Without `--drafts` only `cards/` is read, and an invalid draft does not matter. The one exception: a published card may link to a card that exists only in `drafts/` (held back). The public build shows that link on the map page as the target's name followed by "(not yet published)", with no link and no page, and leaves it out of the map; a target in neither folder is still an M2 error. With `--drafts` a draft replaces the card with the same slug, every page gets the banner "Draft preview — not published" and `<meta name="robots" content="noindex">`. A draft build is a local preview only, never the public site.
- Unused glossary terms are printed as `warning:` lines. They do not fail the build.

## Public site on GitHub Pages

`.github/workflows/pages.yml` builds the site with `uv run python -m me_atlas.site build` (approved cards only, never `--drafts`) on every push to `main` and on manual start, uploads `build/` and deploys it. Every `uses:` is pinned to a commit SHA; `tests/test_pages_workflow.py` checks the trigger, the permissions, the pinning and that the build command has no `--drafts`. The workflow needs the repository to be public and Pages enabled with source "GitHub Actions" (a setting on GitHub, not in the repository); both were done on 2026-11-16, and the first run deployed the site. The address is <https://mrstormlars.github.io/ME-Atlas/> (Norwegian: `nb/`). Founder ruling 2026-11-16 in DECISIONS.

### Open data and citation files

Code: `src/me_atlas/export.py` (pure functions: cards and map content in, text out), written by `site.build`. The build writes a folder `data/` at the top of the output directory, shared by both languages like `static/`:

| File | Content |
| --- | --- |
| `data/me-atlas.json` | A `dataset` block (title, build date as the version, site and repository URLs, licence `CC-BY-4.0`, the rights note, the citation text, the language note, the no-expert-review statement, `draft_preview`, `counts`), then `cards` (every field of `docs/card-format.md`), `symptoms` and `questions` (id and English name or text). |
| `data/hypotheses.csv` | One row per card: slug, name, level, layer, contested rungs, the two badge values, supporting, contradicting and other study counts, links out, long COVID. |
| `data/studies.csv` | One row per study per card: the card slug and every study field. |
| `data/links.csv` | One row per link: source slug, target, target kind (card, symptom, question), target name, support, text, sources. |
| `data/card-format.md` | A byte copy of `docs/card-format.md` (the build argument `card_format`, default the repository's own file). The only definition of the fields. |
| `data/README.txt` | Build date, licence, how to cite, one line per file. |
| `data/citations/<slug>.bib`, `.ris` | One BibTeX and one RIS file per card, one entry per study in card order. |

Lists inside a CSV cell are joined with `; `. CSV is UTF-8 with a header row, CRLF line ends and RFC 4180 quoting. `counts` gives `cards`, `study_rows` (studies summed over cards), `distinct_studies` and `links`; they equal the CSV row counts, and `cards` and `links` equal what the gaps page shows (`tests/test_export.py`).

Everything is derived from the cards the build shows and from `content/symptoms.yaml` and `content/open-questions.yaml`; nothing is looked up and `data/cache/` is not read. No text is written about any card. The dataset is English only; the Norwegian translations stay in the repository (`translations/nb/`) and the JSON, the README and the data page say so. A `--drafts` build sets `"draft_preview": true` and a notice in `README.txt` and on the data page; a public build has `false`.

The citation files carry only what the cards hold. BibTeX: a study with `authors` and `journal` is an `@article` (key the study id without the colon, `pmid12345678`) with `author` (the names joined by ` and `, each in braces so a multi-part surname stays one name), `title`, `journal`, `year`, `doi` (when the card has one), `url` and `note = {PMID: ...}`; a study without them stays `@misc` with `title`, `year`, `url` and `note = {PMID: ...}` or `doi = {...}`. The BibTeX special characters in titles, names and journals (`{ } % & $ # _ ~ ^ \`) are escaped. RIS: `TY  - JOUR` (`UNPB` for a preprint), one `AU` line per author, `TI`, `JO`, `PY`, `DO` (when the card has a DOI), `UR`, `AN  - PMID:...` or `DO  - ...`, `ER  - `, CRLF line ends; without the bibliographic fields only the tags the card supports. `studies.csv` has `authors` (joined with `; `), `journal` and `doi` columns. The fields are copied by code from the PubMed record (`docs/card-format.md`). Each card page links to its two files under the studies heading and to the data page.

`CITATION.cff` at the repository root (CFF 1.2.0) names the authors as the entity "ME Atlas contributors" and carries `doi: 10.5281/zenodo.24333249`. `.zenodo.json` at the repository root says `upload_type: dataset` with the same title, creators, description, licence and keywords as `CITATION.cff`. Both files exist because they are read by different tools: GitHub reads `CITATION.cff` for its "Cite this repository" box, and Zenodo's GitHub integration reads `.zenodo.json` instead of `CITATION.cff` when it exists, and without it would file the archive as software. `tests/test_export.py` checks that the two agree on title, licence and creator name. That DOI is the Zenodo concept DOI, which points to every archived version; each version is a snapshot of the repository at a GitHub release. The constant `DATASET_DOI` in `src/me_atlas/export.py` is the one source: the citation text ends with the DOI link, the dataset block of `me-atlas.json` has `doi` and `doi_url`, `README.txt` has a DOI line, and the data page links it with one sentence saying what the archive is (the files on the page are built from the current cards and are not in the archive). `tests/test_export.py` checks that this DOI is in the data pages, the README, the JSON and `CITATION.cff` and that the version DOI is not. The card pages and the per-card `.bib` and `.ris` files carry no DOI.

### Registered studies on the card page and in the data

A card page with N ≥ 1 listed registered studies shows one line (`card.trials`, class `trials-line`) with N and a link to that card's table on `trials.html`; with N = 0, or when the page is not built, nothing. The data folder always holds `trials.csv` (one row per registry entry, matched or not, ongoing or not, `hypotheses` joined with `; `, columns in `export.TRIALS_COLUMNS`) and `me-atlas.json` gets a `trials` list with the same entries and `dataset.trials_fetched`; both are empty when the project has no `registry/trials.yaml`. The build reads `registry/trials.yaml` and `registry/reliability.yaml` next to `cards/` (option `registry_dir`), validates the first with the same checks as `trials check` (an invalid file stops the build) and treats a reliability file without a true or false `passed` as an error.

### Sources in text

Each sourced text (core claim, level reason, contested reason, badge reasons, subgroups, early signals) ends with numbered references such as `[1] [2]`. A level reason, contested reason or badge reason written as paragraphs (see `docs/card-format.md`) is shown as one paragraph per item, each with its own references; numbering still follows page order. Numbers are per page, in order of first citation, and each links to that study's entry on the same page (`#study-pmid:12345678`). Studies link out to PubMed (`https://pubmed.ncbi.nlm.nih.gov/<pmid>/`) or `https://doi.org/<doi>`. Each study shows its title, one metadata line (year, id, patients and controls, the case definition in plain words with its flag, design, direction, and "cited as [n]") and the finding. Missing numbers read "patients: not stated" and "controls: not stated"; an uncontrolled study without a control number reads "controls: none (uncontrolled study)". The case-definition sentence quoted on the card is not shown on the page.

Case definitions in plain words: Fukuda, Holmes 1988 and `CDC_unspecified` ("CDC criteria (version not stated)") carry the flag "does not require PEM", Oxford the flag "broad"; `unverified` reads "case definition not yet checked", `none` "no case definition stated", `other` "other definition".

Replication status has no field of its own; it is carried by the level name ("Repeated by others") and the level reason.

## Glossary

`content/glossary.yaml` is a list of entries and the only source of English explanations (the Norwegian ones are in `content/glossary.nb.yaml`, see `docs/translation.md`):

```yaml
- term: PEM
  aliases: [post-exertional malaise]
  explanation: Post-exertional malaise. Symptoms get worse after physical or mental effort, often a day or more later.
```

Rules (checked on every build and in `tests/test_glossary.py`): terms and aliases are unique across the file (exact spelling); the explanation is not empty and at most 200 characters; none of the banned words (promising, breakthrough, cure, hope, proven) appears anywhere in an entry. Explanations describe concepts; they do not state findings or causes. A new entry should be read by `card-reviewer` for accuracy and plain language.

**Auto-marking.** In sourced texts and study findings the generator marks the first occurrence on each page of each term or alias. Matching is whole-word and case-sensitive ("Widget" does not match "widget"; add a capitalised alias if you need one). Where matches overlap, the longest wins. Study titles, links and headings are never marked. A term already marked on a page is plain text afterwards. Technical words that are not in the glossary are simply left unmarked.

**Template labels** (ladder names, "contested", "PEM", case definitions and so on) are marked in the templates through one macro, `gloss("term")`, which also follows the first-occurrence rule. A template that names a term missing from the glossary stops the build.

**Behaviour.** A marked term is a `<button>` with a dotted underline and `aria-describedby` pointing at an element on the same page that holds the explanation. It opens on hover, focus and click or tap; Escape or a click elsewhere closes it. Without JavaScript the explanations are listed at the end of the page. The glossary page repeats the same text.

## Accessibility and limits

Body text is 18 px; secondary text (ladder key, legend, readouts, study details, chips, footer, banner) is 16 px (0.889rem) and never smaller, which a test enforces on the stylesheet (only the visually hidden `.sr` rule is exempt); the layout reflows at 200% text size and at 375 px width (tables become stacked lists); tap targets are at least 44 px (marked terms and reference links get an invisible 44 px hit area that does not change the line height); focus is outlined; reduced motion is respected; no pop-ups. Colours are CSS variables at the top of `site.css`; `tests/test_site.py` checks the text pairs against 4.5:1 and chart marks and the focus outline against 3:1. If you change a colour, run the tests. The browser check (375 px, keyboard, one glossary term by focus and click) is manual.

Not built: search, filters, languages other than English and Norwegian, dark mode. The generated `build/` directory is gitignored.
